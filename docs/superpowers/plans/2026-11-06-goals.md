# Goals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Goals ready-made report. Each row is one goal (a practice, at least or no more than, an amount, and a day, week or month), showing the running period's progress and the last 12 periods as squares.

**Architecture:** A new `Goals` template and a `Goals` panel kind in the `panels` format. The server returns these reports only at `panels=4`, and never through `/share`. The client works everything out from `Year` report data ending today, in a new pure module `goalLogic.ts`, and draws it with a new `GoalsPanelView`. The form is one more draft kind in `TemplateForm`.

**Tech Stack:** Rust (actix-web, serde, Diesel tests on a real Postgres), React + TypeScript, Vitest, i18next (en/ru/uk).

**Spec:** `docs/superpowers/specs/2026-11-02-goals-design.md`. Report templates background: `docs/superpowers/specs/2026-10-31-report-templates-design.md`.

**Mockups:** `Goals.dc.html` in the claude.ai/design project "Sadhana Redesign", frames `16m*`, `16t*` and `16d*`, read through the `claude_design` MCP. The mockup wins on layout and visuals, and the spec wins on behaviour.

## Global Constraints

- `GET /reports` returns a report holding a `Goals` panel only when `panels` is 4 or more. At 3, 1 (`true`) or 0 (missing) it's left out. `GET /share/{id}/reports` never returns it, at any level.
- JSON shape (the Rust type is the contract): template `{"Goals": {"goals": [Goal]}}`, panel `{"kind": "Goals", "goals": [Goal]}`, `Goal = {"practice": uuid, "direction": "AtLeast"|"AtMost", "amount": i32, "period": "Day"|"Week"|"Month", "counts": "Total"|"Days"}`. `version` stays 1.
- Goals per report: 1 to 12. At least needs `amount >= 1`. No more than allows `amount >= 0`.
- A goal's practice is Bool, Int or Duration. `counts` matters only for Duration, and is `Total` otherwise.
- Weeks run Monday to Sunday. Months are calendar months. Use local `yyyy-mm-dd` dates only, never `toISOString()`. Use the helpers in `features/today/date.ts`.
- The 90% fill cap applies to every partly filled square.
- No praise, streaks, exclamation marks or pace demands ("13 a day to reach it"). "Days left" is fine.
- Durations use `formatDuration` (`6h 14m`).
- Every new string goes in `public/locales/{en,ru,uk}/translation.json`, with ru/uk plural forms (`_one`, `_few`, `_many`, `_other`). `locales.test.ts` must pass.
- Don't hand-edit `server/src/schema.rs`. No migration is needed.
- Run Rust from the dev container: `docker exec <container> bash -lc 'cd /workspaces/sadhana-pro && make test T=report'`. Run `npm test` with Node 22, never the host's Node 26.

## Review Focus

1. **A logged day with this practice blank:** it counts as 0, so a week where the user logged other practices but not this one is a 0 for an at-least goal (an empty part square), not blank. Pinned in Task 3.
2. **A no-more-than goal over a month with nothing logged:** blank, never full. A full square would read as a perfect month. Pinned in Task 3.
3. **A week that crosses a month or year boundary** (Mon 29 Dec 2025 – Sun 4 Jan 2026), and today being a Sunday: the running week is the one ending today, not the next one. Pinned in Task 3.
4. **A Duration goal by Days:** a day counts when its minutes are above 0, and its amount reads "days", not `h:mm`. Pinned in Tasks 3 and 6.
5. **A cached build at level 3:** it must never receive a Goals report, from the server or from the persisted query cache. Pinned in Tasks 1 and 2.

### Task 3: Goal logic

**Files:**
- Create: `app-react/src/features/insights/panels/goalLogic.ts`
- Test: `app-react/src/features/insights/panels/goalLogic.test.ts`

**Interfaces:**
- Consumes: `Goal` (Task 2), `Lookup` and `makeLookup` from `panelLogic.ts`, `ReportDataEntry`.
- Produces:
  - `periodOf(cob: string, period: GoalPeriod): { from: string; to: string }` gives the day, the Monday-to-Sunday week, or the calendar month holding `cob`.
  - `loggedDays(entries: ReportDataEntry[]): Set<string>` collects dates where any entry's value is neither `null` nor `undefined`.
  - `goalAvailable(goal: Goal, l: Lookup): boolean` is true when the practice is available as Bool, Int or Duration.
  - `type SquareState = 'full' | 'part' | 'limit' | 'over' | 'blank'`
  - `interface GoalSquare { from: string; to: string; value: number; running: boolean; state: SquareState; fill: number }`. `fill` runs from 0 to 1: 1 for full, at most 0.9 for part, 0 otherwise.
  - `squareState(direction: Direction, x: number, n: number, running: boolean, blank: boolean): { state: SquareState; fill: number }`
  - `goalSquares(goal: Goal, l: Lookup, logged: Set<string>, todayCob: string): GoalSquare[]` lists the squares oldest first, with the last one running, and at most 12.
  - `daysLeft(square: GoalSquare, todayCob: string): number | null` counts days to the period's end, today included. It's null for a Day goal.

Period value: sum over days from `from` to `min(to, todayCob)`. Bool counts days with `l.value === 1`, and Int sums the values. Duration with `Total` sums minutes, and with `Days` counts days above 0. A blank counts as 0. A past period is blank when none of its days is in `logged`. The running period is never blank. The first square is the period holding the earliest date with a non-null `l.value` for the practice, but no more than 11 periods before the running one. With no values at all there is only the running square.

Square rule (copy from the spec; `x` is the value, `n` the amount):

| Direction | Condition | state, fill |
|---|---|---|
| any | past and blank | `blank`, 0 |
| AtLeast | `x >= n` | `full`, 1 |
| AtLeast | `x < n` | `part`, `min(x / n, 0.9)` |
| AtMost | `x = 0` | `full`, 1 |
| AtMost | `0 < x < n` | `part`, `min((n - x) / n, 0.9)` |
| AtMost | `x = n`, `n > 0` | `limit`, 0 |
| AtMost | `x > n` | `over`, 0 (running too) |
